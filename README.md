# Telegram Sale Manager

Основа для собственного Telegram-бота, который собирает заявки клиентов и передаёт их менеджеру. Проект можно адаптировать под свой магазин, закупки под заказ или приём запросов на товары.

Telegram-бот для приёма заявок на автозапчасти и другие товары. Написан на TypeScript с grammY; хранит заявки в SQLite через встроенный `node:sqlite`.

Бот принимает описание, фото или документ с подписью, VIN для автозапчастей, ФИО, телефон и город. Перед сбором контактов запрашивает согласие. Клиент проверяет заявку перед отправкой, видит свои последние заказы и может дополнять открытые заявки. Сохранённые контакты и автомобиль можно использовать повторно.

Уведомления менеджеру, Google Sheets и Google Tasks / TasksBoard подключаются отдельно. Вложения пересылаются средствами Telegram: бот не скачивает и не исполняет их. Название магазина, контакт поддержки, условия доставки, текст согласия и часовой пояс задаются в локальном `.env`. Публичные значения по умолчанию не привязаны к конкретному владельцу.

## Что потребуется

- Node.js и npm, Git и компьютер или сервер, который сможет постоянно выполнять процесс бота.
- Собственный Telegram-бот и токен от BotFather.
- Для изменения сценария — базовые знания TypeScript.
- Для Google-интеграций — собственный Google Cloud проект и учётные данные. Для запуска без интеграций Google-аккаунт не нужен.

Домен, HTTPS-сертификат и публичный входящий порт для обычного запуска не требуются: бот получает обновления через long polling. Постоянная работа требует доступного соединения с Telegram и работающего процесса.

## Быстрый старт

### 1. Скопируйте проект

Сделайте fork репозитория в свой GitHub-аккаунт, затем клонируйте **свою** копию. Замените `YOUR_ACCOUNT` и `YOUR_REPOSITORY` в команде:

```bash
git clone https://github.com/YOUR_ACCOUNT/YOUR_REPOSITORY.git
cd YOUR_REPOSITORY
```

### 2. Установите зависимости


Используйте поддерживаемую LTS-версию Node.js; в CI используется Node.js 24. Минимальное требование проекта — Node.js 22.5 с `node:sqlite`.

```bash
npm ci
cp .env.example .env
chmod 600 .env
```

Команды приведены для Linux/macOS. В PowerShell файл можно скопировать командой `Copy-Item .env.example .env`; права доступа к секретам настройте средствами Windows.

### 3. Создайте своего бота

Откройте [@BotFather](https://t.me/BotFather), отправьте `/newbot` и задайте имя и username. Полученный токен запишите в `BOT_TOKEN` в локальном `.env`. Не отправляйте токен в Issues и не вставляйте его в исходный код.

Для первого запуска достаточно заполнить только `BOT_TOKEN`. Остальные значения можно оставить пустыми: заявки будут сохраняться в локальной SQLite-базе без отправки менеджеру и в Google.

### 4. Запустите и проверьте сценарий

Запустите бота:

```bash
npm start
```

Откройте своего бота в Telegram, нажмите **Start** и оформите пробный заказ:

1. Выберите «Новый заказ» и подтвердите согласие на обработку данных.
2. Выберите «Другой товар» — для этой ветки VIN не требуется.
3. Введите описание, продолжите заполнение и укажите тестовые контактные данные.
4. Проверьте заявку и подтвердите её.
5. Выполните `/orders` и убедитесь, что заказ появился. Из другого Telegram-аккаунта он отображаться не должен.

До приёма реальных заказов замените тексты и контакты по инструкции ниже и подключите уведомления менеджеру.

Для разработки: `npm run dev`. Для сборки и запуска:

```bash
npm run build
npm run start:prod
```

Не запускайте несколько экземпляров с одним токеном и одной SQLite-базой. По умолчанию база создаётся в `data/orders.sqlite3`. Черновики живут в памяти, истекают после 30 минут бездействия и теряются при перезапуске.

## Адаптация под свой бизнес

Для настройки бренда исходники менять не требуется. Добавьте свои значения в локальный `.env` и перезапустите бота:

```dotenv
SHOP_NAME="Мой магазин"
SUPPORT_TELEGRAM_USERNAME=
DELIVERY_TERMS="Срок и стоимость доставки согласует менеджер."
CONSENT_TEXT=
TIME_ZONE=UTC
```

В `SUPPORT_TELEGRAM_USERNAME` укажите свой Telegram username с `@` или без него, без URL. Если значение пустое, кнопка обратной связи и подписи с контактом не показываются. В `.env.example` оставлены только нейтральные значения; свой ник, название бизнеса и рабочие ID храните только в `.env` или переменных окружения сервера.

`CONSENT_TEXT` заменяет стандартный текст запроса согласия. Пустое значение включает встроенный текст; адаптируйте его к реальной обработке данных. Текстовые настройки выводятся как обычный текст, а в HTML-сообщениях экранируются. `TIME_ZONE` принимает имя часового пояса IANA; по умолчанию используется `UTC` для Telegram, Google Sheets и Google Tasks.

| Что изменить | Где настроить | Что проверить |
| --- | --- | --- |
| Название магазина | `SHOP_NAME` | Клиент видит ваш бренд |
| Контакт поддержки и ссылку кнопки | `SUPPORT_TELEGRAM_USERNAME` | Кнопка ведёт к нужному аккаунту; при пустом значении скрыта |
| Сроки и условия доставки | `DELIVERY_TERMS` | Условия совпадают в подтверждении, ответе клиенту и сообщении менеджеру |
| Согласие на обработку данных | `CONSENT_TEXT` | Текст соответствует фактическим целям обработки |
| Часовой пояс вывода дат | `TIME_ZONE` | Даты отображаются в нужном поясе во всех интеграциях |
| Категории и вопросы анкеты | Клавиатуры, `NewOrderStep` и обработчики в `src/bot.ts` | Новые поля проходят весь сценарий, включая повторное заполнение |
| Формат VIN, телефона, ФИО, города | `src/validation.ts` и соответствующие обработчики | Правила подходят вашим клиентам |
| Столбцы Google Sheets | `HEADERS` и `appendOrder` в `src/googleSheets.ts` | Заголовки, диапазоны и формулы изменены согласованно |
| Заголовок и описание задачи | `createOrder` в `src/googleTasks.ts` | Менеджеру передаются нужные поля |
| Ограничения нагрузки | `src/security.ts`, `src/database.ts`, `src/bot.ts` | Лимиты согласованы на уровне интерфейса и базы |

Для магазина без автозапчастей можно сначала пользоваться веткой «Другой товар». Если хотите полностью убрать автотематику, измените также выбор категории, вопросы, помощь и проверки VIN. Новые сохраняемые поля требуют изменений в `NewOrder`/`ExportOrder`, схеме и запросах `src/database.ts`, а также в экспорте и тестах.

После правок выполните `npm run check` и `npm run build`, затем пройдите обе ветки оформления вручную. Работающая production-сборка использует `dist`: после изменения исходников её нужно пересобрать и перезапустить.

## Подключение менеджера

### Личный чат

1. Запустите бота с заполненным `BOT_TOKEN`.
2. С аккаунта менеджера откройте бота и отправьте `/start`, затем `/myid`.
3. Запишите полученный ID в `ADMIN_CHAT_ID` в `.env`.
4. Если нужна команда `/bindorder`, запишите личный ID менеджера также в `ADMIN_USER_IDS`.
5. Перезапустите бота и оформите тестовый заказ с клиентского аккаунта.

Бот должен отправить менеджеру данные заказа и контакты. Пользователь должен сначала открыть чат с ботом, чтобы бот мог отправлять ему сообщения.

### Закрытая группа и темы

1. Создайте закрытую группу менеджеров, добавьте бота и разрешите ему отправлять сообщения и вложения.
2. Отправьте `/chatid` в группе. Если Telegram не передаёт команду боту, используйте `/chatid@YOUR_BOT_USERNAME`.
3. Запишите ID группы в `ADMIN_CHAT_ID`, сохранив знак минус.
4. Для группы с темами отправьте команду внутри нужной темы и запишите её ID в `ADMIN_MESSAGE_THREAD_ID`.
5. Для `/bindorder` укажите в `ADMIN_USER_IDS` **личные ID** доверенных менеджеров через запятую. Это не ID группы; менеджер может узнать свой ID через `/myid` в личном чате с ботом.
6. Перезапустите процесс и проверьте доставку нового заказа и дополнения к нему.

Все участники группы уведомлений видят присланные туда контакты клиентов. Ограничьте состав группы. Сам бот не нуждается в доступе ко всем сообщениям группы для клиентского оформления: оно происходит в личных чатах.

## Настройки

Все значения задаются локально в `.env`; безопасный шаблон — `.env.example`.

| Переменная | Назначение |
| --- | --- |
| `BOT_TOKEN` | Обязательный токен Telegram-бота |
| `SHOP_NAME` | Название магазина, по умолчанию «Магазин»; до 120 символов |
| `SUPPORT_TELEGRAM_USERNAME` | Необязательный Telegram username поддержки; пусто — контакт скрыт |
| `DELIVERY_TERMS` | Условия доставки; до 600 символов |
| `CONSENT_TEXT` | Текст согласия; до 2000 символов; пусто — стандартный текст |
| `TIME_ZONE` | Часовой пояс IANA, по умолчанию `UTC` |
| `DATABASE_PATH` | Путь к SQLite, по умолчанию `data/orders.sqlite3` |
| `ADMIN_CHAT_ID` | Чат для уведомлений: личный чат менеджера или закрытая группа |
| `ADMIN_MESSAGE_THREAD_ID` | Необязательный ID темы группы |
| `ADMIN_USER_IDS` | Telegram ID доверенных пользователей через запятую; разрешает `/bindorder` только в `ADMIN_CHAT_ID` |
| `GOOGLE_SHEETS_SPREADSHEET_ID` | ID вашей Google-таблицы |
| `GOOGLE_SHEETS_SHEET_ID` | Числовой `gid` листа, включая `0` |
| `GOOGLE_SERVICE_ACCOUNT_JSON` | Путь к JSON-ключу service account |
| `GOOGLE_SERVICE_ACCOUNT_EMAIL`, `GOOGLE_PRIVATE_KEY` | Альтернатива JSON-ключу; переносы строк ключа можно записать как `\n` |
| `GOOGLE_TASKS_CREDENTIALS_FILE` | Путь к пользовательскому OAuth-токену Google Tasks |
| `GOOGLE_TASKS_LIST_ID` | ID списка задач |

Без `ADMIN_USER_IDS` команда `/bindorder` отключена. Само нахождение в группе менеджеров прав не даёт. Уведомления менеджеру не требуют настройки этой команды.

## Команды

| Команда | Действие |
| --- | --- |
| `/start` | Главное меню |
| `/new` | Оформить заявку |
| `/orders` | Показать свои последние заказы |
| `/cancel` | Сбросить текущее заполнение |
| `/myid` | Узнать свой Telegram ID в личном чате |
| `/chatid` | Узнать ID текущего чата и темы |
| `/bindorder 29` | Привязать заказ к карточке бота: отправляется ответом на карточку, доступна только доверенным менеджерам |

Оформление, просмотр и клиентские кнопки работают только в личном чате. Заказ содержит до 10 позиций, включая дополнения; создать можно до 5 заказов за час на пользователя. Действуют ограничения 30 обновлений за минуту на пользователя и 600 на экземпляр бота; лишние обновления игнорируются. Это базовая защита от спама, которую следует адаптировать к нагрузке.

## Google Sheets

1. В своём Google Cloud проекте включите Google Sheets API и создайте отдельный service account.
2. Сохраните его ключ вне публикуемых файлов, например в `secrets/service-account.json`, с правами `600`.
3. Откройте доступ «Редактор» только к нужной таблице для email service account. Не делайте таблицу публичной и не выдавайте аккаунту роли администратора проекта.
4. Заполните ID таблицы, `gid` листа и путь к ключу в `.env`.

ID таблицы берётся из адреса между `/d/` и `/edit`, а ID листа — из `gid`:

```text
https://docs.google.com/spreadsheets/d/YOUR_SPREADSHEET_ID/edit#gid=0
```

Пример настройки своей таблицы:

```dotenv
GOOGLE_SHEETS_SPREADSHEET_ID=YOUR_SPREADSHEET_ID
GOOGLE_SHEETS_SHEET_ID=0
GOOGLE_SERVICE_ACCOUNT_JSON=secrets/service-account.json
```

Начните с отдельной пустой таблицы: существующая рабочая таблица может иметь другой формат. Текущая раскладка содержит столбцы клиента, товара, цены, оплаты, доставки, себестоимости и прибыли, но **бот не рассчитывает все эти бизнес-показатели** и не заполняет все поля автоматически. Он записывает сведения заявки и формулу числа дней с заказа; остальную работу с таблицей нужно настроить под себя.

На каждую позицию записывается строка. Пустой лист получает заголовки; если существующие заголовки отличаются, экспорт отменяется, чтобы не повредить таблицу. Формат столбцов определён в `src/googleSheets.ts`. Пользовательские значения записываются через `RAW`, чтобы не выполнялись как формулы; служебные даты и формулы записываются отдельно.

## Google Tasks / TasksBoard

TasksBoard отображает задачи из Google Tasks; бот использует Google Tasks API.

1. Включите Google Tasks API и настройте OAuth consent screen в своём Google Cloud проекте.
2. Создайте OAuth client типа **Desktop app**, скачайте его в `google-tasks-oauth.json` в корне проекта. Ограничьте доступ к файлу: `chmod 600 google-tasks-oauth.json`.
3. На доверенном компьютере с браузером выполните `npm run authorize:tasks` и откройте выведенную ссылку на этом же компьютере. Нужны полные зависимости, установленные через `npm ci`.
4. Выберите нужный Google-аккаунт. Скрипт сохранит `google-tasks-token.json` с правами `600` и выведет ID доступных списков.
5. Укажите путь к токену и ID списка в `.env`.

Пример локальной настройки после авторизации:

```dotenv
GOOGLE_TASKS_CREDENTIALS_FILE=google-tasks-token.json
GOOGLE_TASKS_LIST_ID=YOUR_TASK_LIST_ID
```

Проверьте новый заказ: в выбранном списке должна появиться задача с контактами и позициями. Сейчас задача создаётся при оформлении заказа; последующие дополнения не синхронизируются с уже созданной задачей. Изменения в TasksBoard не меняют заказ в SQLite.

OAuth-файлы исключены из Git. Токен даёт доступ к Google Tasks пользователя: используйте отдельный рабочий аккаунт. При режиме OAuth Testing может потребоваться повторная авторизация согласно настройкам Google.

## Развёртывание на Linux

Пример systemd unit: [deployment/bot-sale-manager.service](deployment/bot-sale-manager.service). Он рассчитан на пользователя и группу `botmanager`, каталог `/opt/bot-sale-manager` и Node.js в `/usr/bin/node`. Перед установкой создайте этого пользователя и каталог `data`, скорректируйте пути.

Код и `node_modules` должны принадлежать пользователю развёртывания и быть доступны боту только для чтения; запись разрешена только в `data`. Файлы `.env` и Google-ключи должны читаться только владельцем и, при необходимости, группой `botmanager` (`640`). Для секретов, принадлежащих самому `botmanager`, используйте `600`. В unit включены `NoNewPrivileges`, ограничение системных каталогов, пустой набор capabilities и `UMask=0077`.

```bash
npm ci
npm run check
npm run build
npm prune --omit=dev
sudo install -m 644 deployment/bot-sale-manager.service /etc/systemd/system/bot-sale-manager.service
sudo systemctl daemon-reload
sudo systemctl enable --now bot-sale-manager
sudo systemctl status bot-sale-manager
```

Локальная OAuth-авторизация выполняется до `npm prune`, затем на сервер передаётся только необходимый токен. Бот использует long polling: входящий HTTP-порт не нужен. Ограничьте SSH, включите обновления ОС, контролируйте свободное место и доступ к резервным копиям. Проверяйте unit на целевой системе.

Заказы сохраняются до отправки внешних уведомлений. Если Telegram или Google API недоступен, заказ остаётся в SQLite, но автоматической очереди повторной доставки нет. Контролируйте ошибки сервиса и сверяйте данные. SQLite и резервные копии не зашифрованы приложением; используйте шифрование диска и ограниченный доступ. Для согласованной резервной копии используйте SQLite backup API/`.backup` либо остановите сервис; не копируйте только основной файл работающей базы в режиме WAL.

## Структура проекта

```text
src/
  main.ts          # Сборка компонентов, запуск и остановка
  config.ts        # Чтение и проверка переменных окружения
  branding.ts      # Настройки бренда, поддержки, согласия и часового пояса
  bot.ts           # Диалоги, кнопки и уведомления Telegram
  database.ts      # SQLite, заказы и проверки принадлежности
  validation.ts    # Правила проверки полей
  security.ts      # Лимиты, срок хранения черновиков, проверка менеджера
  googleSheets.ts  # Экспорт позиций в Google Sheets
  googleTasks.ts   # Создание задач Google Tasks
scripts/
  authorizeGoogleTasks.ts  # Локальная OAuth-авторизация
  checkSecrets.mjs         # Проверка файлов перед публикацией
tests/                      # Автоматические тесты

```

Новая версия схемы SQLite добавляет недостающие таблицы и предусмотренные кодом столбцы при запуске. Это не полноценная система миграций: перед изменением структуры базы делайте согласованную резервную копию и проверяйте обновление на копии данных.

## Ограничения текущей версии

- Это сборщик заявок: оплаты, каталога, складского учёта и веб-кабинета менеджера нет.
- Статусы `new`, `processing`, `completed`, `cancelled` предусмотрены в базе, но интерфейс и команды их изменения не реализованы. Google Sheets и TasksBoard не управляют статусами SQLite.
- Дополнение доступно только владельцу заявки в статусе `new` или `processing`, до общего лимита 10 позиций.
- Заказ сохраняется локально, а интеграции получают отдельные копии данных. Двусторонней синхронизации и гарантированной доставки нет.
- Основной сценарий рассчитан на один процесс и локальную SQLite-базу. Вложения остаются в Telegram, а не в собственном файловом архиве.
- Автоматического удаления данных клиентов, мультиязычного интерфейса и панели управления настройками нет; бренд настраивается через окружение.

## Частые проблемы

| Проблема | Что проверить |
| --- | --- |
| Бот не запускается | Версию Node.js, установлен ли `npm ci`, заполнен ли `BOT_TOKEN` в `.env` текущего каталога |
| Запуск `start:prod` не находит файл | Выполните `npm run build`; запускайте команды из корня проекта |
| Бот перестал получать сообщения | Не запущен ли второй процесс с тем же токеном; доступен ли Telegram с сервера |
| Менеджеру ничего не приходит | Менеджер нажал `/start`; `ADMIN_CHAT_ID` правильный; бот состоит в группе и может писать; для тем указан верный ID |
| `/bindorder` ничего не делает | Команда отправлена из `ADMIN_CHAT_ID` доверенным пользователем из `ADMIN_USER_IDS` в ответ на сообщение самого бота |
| После настройки интеграция не появилась | Процесс перезапущен; набор переменных заполнен полностью; пути к ключам доступны пользователю сервиса |
| Google Sheets не принимает строки | API включён, таблица доступна service account, `gid` правильный, заголовки совпадают с `HEADERS` |
| OAuth-ссылка не завершает авторизацию | Ссылка открыта на компьютере со скриптом, не истекли 5 минут; используется Desktop OAuth client и разрешён нужный аккаунт |
| Кнопки перестали работать или анкета сбросилась | Истёк срок черновика, был перезапуск или достигнут лимит; начните через `/new`, при ограничении частоты подождите минуту |
| Заказ есть, но экспорт отсутствует | Проверьте ошибки сервиса и соответствующий API; автоматического повторного экспорта нет |

При обращении за помощью указывайте версию Node.js, команду запуска, обезличенный сценарий и результат проверки. Не прикладывайте `.env`, Google JSON-ключи, базу и реальные контакты.

## Проверки

```bash
npm run check
npm run build
npm run security:secrets
npm audit
```

Проверяются типы, валидация, принадлежность заказов, права менеджера и ограничения ресурсов. CI выполняет проверки без production-секретов. Dependabot предлагает обновления npm и GitHub Actions. Локальная OAuth-авторизация использует loopback-адрес `127.0.0.1`, случайный порт, проверку `state`, PKCE и таймаут 5 минут.

## Публикация на GitHub

Не загружайте всю папку проекта через браузер и не делайте архив с `.env`, базой и ключами. Используйте Git: локальные секреты, `.deploy`, базы, резервные копии и зависимости исключены через `.gitignore`.

```bash
npm run security:secrets
# Проверьте список: здесь не должно быть данных клиентов или ключей.
git status --short
# После проверки подготовьте первый коммит.
git add .
npm run security:secrets
git diff --cached --stat
git commit -m "Prepare Telegram sale manager for GitHub"
git remote add origin https://github.com/YOUR_ACCOUNT/YOUR_REPOSITORY.git
git push -u origin main
```

Проверка секретов также проверяет уже отслеживаемые файлы: `.gitignore` не защищает файлы, добавленные раньше. Сканер использует ограниченный набор шаблонов и не заменяет ручную проверку. После создания репозитория настройте защиту основной ветки, обязательные CI-проверки, secret scanning и push protection, если они доступны. См. [инструкцию GitHub](https://docs.github.com/en/code-security/how-tos/secure-your-secrets/prevent-future-leaks/enable-push-protection).

## Безопасность и распространение

Ограничения защиты и действия при утечке описаны в [SECURITY.md](SECURITY.md). У каждого независимого развёртывания должны быть свои bot token, база, Google-ключи, список менеджеров, контакт поддержки и настройки интеграций. Личные значения храните в исключённом из Git `.env` или в окружении сервера; не переносите их в публичный шаблон. Проверяйте также историю коммитов и email автора коммитов перед публикацией. Не распространяйте готовую копию со своими рабочими секретами и данными клиентов.
